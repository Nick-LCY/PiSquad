### Commit 1 — `fix(cli): copy docs payload in core channel`（C1，最关键）

**Bug**：`installCore` 从不拷贝 `assets/docs/` 到 `<target>/docs/`。pi-squad 的 Docs 层（文档库模板）是核心 payload，旧 bash 明确 `cp -r assets/docs`，PRD/README 都承诺会拷，当前完全遗漏。

**先验证 bug 存在**：`npm run build` 后 `node dist/bin.js install /tmp/c1verify --yes`，确认 `/tmp/c1verify/docs/` **不存在**。清理后修。

**修复**：在 `src/lib/plugins/core.ts` 的 `installCore` 里，增加拷贝 `docs` 的步骤——`copyDir(resolveAsset("docs"), join(target, "docs"))`（与 agents/skills 同样的 dry-run/error 处理）。core 始终装 docs（docs 属于 core channel，不可选）。

**验证（通过才 commit）**：

### Commit 2 — `fix(cli): add assets-version and unify state reading`（C2 + C3）

**C2**：`assets/.pi/assets-version.txt` 不存在；`version.ts` 的 `resolveAssetsVersion()` 吞掉读取错误、fallback 到 cliVersion，导致每个 `state.json` 的 `version === cliVersion`，破坏 PRD 的双版本分离（cliVersion=工具版本，version=assets 内容版本）。且与 `assets.ts#readAssetsVersion()`（缺失抛错）行为矛盾。

**修复**：
1. **创建 `assets/.pi/assets-version.txt`**，内容为 `0.1.0`（= 当前 package.json version；后续可独立 bump）。**本次修复授权创建这一个 assets/ 文件**（它是 install 的版本依赖，非 payload 内容变更；其余 assets/ 内容仍不动）。
2. `writeState` 路径：`version` 字段改用 `readAssetsVersion()`（读文件，缺失则**抛错**暴露问题），**不再**走 `resolveAssetsVersion` 的 fallback。即 `version = partial.version ?? existing?.version ?? readAssetsVersion()`。
3. `versionCommand`（`src/commands/version.ts`）可保留带 fallback 的展示（容错），即展示时缺失文件退回 cliVersion。
4. 这样区分清楚：写入 state 必须真实读 assets 版本（严格）；展示可容错。

**C3**：`install.ts` 有本地 `readExistingState`（无字段校验，`JSON.parse as InstallState`），`version.ts` 另有一个更严格的。两者对"损坏 state.json"判断不一致（一个当已装、一个当未装）。

**修复**：
1. 在 `version.ts` 导出统一的 `readState(target): InstallState | undefined`（严格校验 version+cliVersion+installedAt+channels 字段；缺失或损坏返回 undefined，或对损坏文件给清晰错误——选择"返回 undefined 并由调用方决定"即可，保持简单）。
2. 删除 `install.ts` 里的本地 `readExistingState`，改用导入的 `readState`。
3. `writeState` 内部合并 existing state 时也用 `readState`（统一入口）。这也为第二阶段 task 10（readState）铺垫。

**验证（通过才 commit）**：
- tsc + build exit 0
- `node dist/bin.js install /tmp/c2 --yes` → state.json 的 `version` 字段 = `"0.1.0"`（来自 assets-version.txt），`cliVersion` 也是 `0.1.0`（值相同但来源不同，语义分离已建立）
- `grep -n "readExistingState" src/` → 仅在 version.ts 内部（或无，若已重命名）；install.ts 不再有本地定义
- 手动写一个损坏的 `/tmp/c2corrupt/.pi/.pisquad/state.json`（内容 `{"foo":"bar"}`），跑 install → 行为一致（按 readState 返回 undefined 处理，即当未装，而非一个路径当已装），清理

### Commit 3 — `fix(cli): atomic gitignore write and codegraph.json copy`（C4 + W1）

**C4**：`install.ts` 的 `appendGitignoreRule` 用 `writeFileSync`（非原子），其余写入都用 `atomicWriteFile`。断电可能损坏用户 `.gitignore`。

**修复**：改用 `atomicWriteFile`——先读现有内容、计算新内容（含追加的 `.pi/.pisquad/`），再原子写入。

**W1a**：codegraph channel 从不拷 `assets/codegraph.json` 到 `<target>/codegraph.json`（旧 bash 拷了，是 `codegraph init` 的配置输入）→ 回归。

**修复**：在 `installCodegraph`（`src/lib/plugins/codegraph.ts`）里，cp `assets/codegraph.json` → `<target>/codegraph.json`。**首次安装路径下目标文件应不存在；若已存在则跳过（不覆盖用户配置）**，并 log。

**W1b**：`.npmignore` 的 `codegraph.json` 未锚定（minimatch 可能误匹配深层）。改为 `/codegraph.json`（锚定根）。

**验证（通过才 commit）**：
- tsc + build exit 0
- `node dist/bin.js install /tmp/c3 --yes --with codegraph` → `/tmp/c3/codegraph.json` 存在；确认 install.ts 的 gitignore 写入用 atomicWriteFile（代码确认）
- 清理

### Commit 4 — `fix(cli): harden copy/target/codegraph robustness`（W2 + W4 + W8 + W10）

**W2**：`copy.ts` 的 `copyDir` 用 `statSync`（跟随符号链接）。assets 树当前无符号链接，但第二阶段 diffTree 会遍历用户 target 树，符号链接是真实风险。

**修复**：改用 `lstatSync`；遇到符号链接时**跳过**（不跟随、不拷贝），用 logger 记一条 warn。保持简单、安全。

**W4**：`resolveTarget` 无校验。注意：install 到任意路径是**合法需求**（用户指定目标，如 `pisquad install ../sibling`），**不要硬拒绝 `..`**。但：
- `~user`（非 `~/`）会静默误展开成相对路径（`cwd/~user/...`）→ 这种情况 log 一条 warn 提示路径异常。
- 确认 `resolveTarget` 返回的是绝对路径，且 install 入口已打印该绝对路径（`logger.info("pisquad install → ${target}")`）——如已有则保持，让用户始终能看到真实目标。

**W8**：`codegraph.ts` 的 `codegraph init` 用 `maxBuffer: 4MB`，大仓库可能溢出导致误导性 warn。

**修复**：把 `codegraph init` 的 maxBuffer 提高到 `64 * 1024 * 1024`（64MB）。（npm install 的 maxBuffer 也一并检查，若也是 4MB 则同步提高。）

**W10**：`default.ts` 用 `logger.step(...)`，但 `step` 只在 verbose 开启时输出，而 MVP 无任何路径 `setVerbose(true)` → 永久静默。

**修复**：改用 `logger.info(...)`（或直接删除该行，因为 commander 已显示分发）。倾向改 info，保留可观测性。

**验证（通过才 commit）**：
- tsc + build exit 0
- 代码确认：copy.ts 用 lstatSync 且跳过符号链接；codegraph.ts maxBuffer=64MB；default.ts 用 logger.info
- `node dist/bin.js`（无参）→ 不再静默（能看到 default→install 的 info，或行为正常）
- 清理临时目录
