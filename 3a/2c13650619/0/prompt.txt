## 范围约束
- 只覆盖 docs 文档库自身使用的术语（结构 / 格式 / 约定类）。
- 保持通用、模板化：**不要**出现 pi、agent（scout/planner/worker/reviewer/archivist）、扩展（entire/codegraph）等词汇——那些属于 workflow skill，不进 docs。
- 每条解释要落在"在本项目（文档库）中的含义"，简明。

## 术语清单（请据此成文，措辞可优化，但术语与含义方向不要跑偏）
1. **结构即导航** — 不靠检索，用目录树 + 每层 README 表达文档间的语义关系，靠 ls/read 下钻。
2. **渐进式披露** — 每层只暴露摘要 + 入口，按需下钻，避免一次性把全部内容灌满上下文。
3. **稳定层 / 流动层** — 文档按变更频率分层：稳定层（architecture、conventions、glossary）很少变；流动层（prds、tasks、current-state）随开发频繁变化。
4. **知识层** — docs/ 目录本身，存放项目结构化知识（区别于代码）。
5. **current-state（当前状态看板）** — docs/current-state.md，高频变更的进度看板，汇总活跃需求、任务状态、TODO；开始任何任务前先读。
6. **PRD（需求设计）** — docs/prds/ 下的需求设计文档，是任务拆分的输入。
7. **Task（任务）** — docs/tasks/ 下从 PRD 拆分出的、可独立完成的开发单元，带 frontmatter status。
8. **ADR（架构决策记录）** — docs/architecture/decisions/ 下的文档，记录某个重要架构决策的背景、决策与影响。
9. **status（任务状态）** — Task frontmatter 字段，取值 todo / doing / done / blocked。
10. **frontmatter** — 文件顶部 `---` 包裹的 YAML 元数据块（如 Task 的 prd、status）。
11. **wikilink** — 文档间引用文件的语法 `[[路径]]`，路径相对 docs/ 根目录，仅指向 docs/ 内已存在的文件。
