### 2. 新增 ADR `docs/architecture/decisions/0002-self-update-version-check.md`

按 ADR 模板（日期/状态:已接受/背景/决策/影响），内容框架：

- **标题**：`0002. self-update 前比较版本，避免重跑死循环`
- **日期**：2026-08
- **状态**：已接受
- **背景**：0.1.0 的 `selfUpdate` 确认全局安装后无条件跑 `npm i -g @nicklin/pisquad@latest`，即使本地已是最新版 npm 也返回成功（exit 0），于是 `selfUpdate` 总返回 `updated:true`，`upgrade` 据此提示"Re-run"——用户重跑又触发 self-update，**陷入死循环**。该 bug 只在包真发布到 registry 后（`npm i -g` 成功）才暴露，发布前的 e2e（含 npm link）因 registry 无此包、npm i -g 直接失败而无法复现。
- **决策**：`selfUpdate` 在跑 `npm i -g` **之前**先 `npm view @nicklin/pisquad version` 取 registry 最新版，与 `readCliVersion()` 比较，三分支：
  1. registry 版本 == 当前版本（已是最新）→ log "already up to date"，返回 `updated:false`，upgrade **继续 project 同步**（死循环消除）
  2. registry 版本 > 当前版本（有新版）→ 跑 `npm i -g`，返回 `updated:true`，upgrade 提示重跑（因进程内存仍是旧代码，需用新代码做同步）
  3. `npm view` 失败（网络/离线）→ warn，返回 `updated:false`，继续同步（保守，宁可漏更新也不死循环）
- **影响**：消除死循环；印证 CLI 版本与 assets 版本独立的设计价值（本次只修 CLI，`assets-version.txt` 仍 0.1.0，package.json 升 0.1.1）；未来维护 self-update 必须保留"先比版本"这一步

并在 `docs/architecture/decisions/README.md` 的清单里加 0002（用 wikilink `[[architecture/decisions/0002-self-update-version-check.md]]`，注意目标文件先创建）。
