## 背景（给 PRD「背景」段用）

pi-squad 的可执行文件 `pisquad` 目前是一个 152 行的单文件 bash 安装器（仓库根），存在诸多缺陷：无子命令分发、无参数解析、无版本管理；交互界面简陋（无颜色、无方向键、必须输数字+回车，且 `</dev/tty` 在 CI/管道里直接 EOF 退出）；永远 `curl` 拉 GitHub main 分支，版本不可控；还存在一个 bug：勾选 entire 时只跑 `entire enable --agent pi` 却从未把 `extensions/entire/` 目录拷进目标。

## 已确认的产品决策（写进 PRD「方案」+ ADR「决策」）

1. **语言**：TypeScript
2. **包名**：`pisquad`（已核实 npm registry 未占用）
3. **分发型式**：npm 全局包（`npm i -g pisquad`）为主；保留一个极简 bash bootstrap（仓库根 `pisquad` 文件）维持 `curl|bash` 入口——它检测 node 后转发到 `pisquad`（已全局安装）或 `npx pisquad@latest`
4. **仓库结构**：**根目录即 npm 包根**——`src/`（TS 源码）、`dist/`（构建产物，gitignored）、`package.json`、`tsconfig.json`、`tsup.config.ts`、`.npmignore` 都在根；`assets/` 保持原位（在根）
5. **assets 内嵌**：组件（`assets/`）打包进 npm 包本体，install/upgrade 都从包内资源拷贝，**不再运行时 curl GitHub tarball**。CLI 版本 = assets 版本，对应清晰

7. **CLI 版本 vs assets 版本分离**：state.json 同时记录 `cliVersion`（工具版本）和 `version`（assets 内容版本，来自包内 `assets/.pi/assets-version.txt`）
8. **upgrade 安全机制**：项目里记 `<target>/.pi/.pisquad/state.json`；upgrade 时用 sha256 diff 检测用户是否改过文件；**覆盖前先 tar.gz 备份到 `<target>/.pi/.pisquad/backups/`**；旧版已安装时 install 拒绝覆盖、强制走 upgrade

10. **不向后兼容**：旧 bash 安装的项目无 state.json，upgrade 会报错提示「未安装，请先 install」；**不写迁移工具**
11. **交互/非交互**：交互用 @inquirer/prompts checkbox 选 codegraph/entire（core 锁死全装）；非交互用 `--yes/--with/--without/--all` + 环境变量 `PISQUAD_WITH/PISQUAD_WITHOUT`；无 tty 自动退化为非交互默认（只装 core），**不再 EOF 卡死**
