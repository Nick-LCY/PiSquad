## 根因(已取证确认,两处代码联手导致 bug)
现象:未传 `--interactive`/`--no-interactive` 且有 tty 时,upgrade 不进 per-file 交互,而是走 all-adopt(modified 被直接 adopt)。

1. `src/commands/upgrade.ts:261` 调用决策层时:
   ```ts
   interactive: options.interactive === true,
   ```
   用户未传 flag 时 `options.interactive === undefined`,被 `=== true` 收窄成 `false`。
2. `src/upgrade/decision.ts:236-241` `shouldPrompt`:
   ```ts
   function shouldPrompt(input: DecisionInput): boolean {
     if (input.yes === true) return false;
     if (input.interactive === false) return false;   // 未传 flag 时 input.interactive===false 必命中
     if (!input.isInteractiveEnv) return false;
     return true;
   }
   ```
   不区分「显式 `--no-interactive`」与「未传 flag」。导致 ADR-0003 §5 的「tty 自动交互」路径永远走不通(`isInteractive()` 在自动交互场景下实际是死代码)。

注意:dry-run 路径(`upgrade.ts:198-212`)硬编码 `interactive:false, interactiveSetByUser:true, isInteractiveEnv:false, yes:true`,不要动它。

## 设计意图(ADR-0003 §5,见 docs/architecture/decisions/0003-interactive-upgrade.md)
- 有 tty 且未指定 flag → 走交互(per-file prompt,modified 默认 keep)
- 无 tty / CI / curl|bash → 退化为 all-adopt + 备份
- `--interactive` / `--no-interactive` 显式覆盖;`--interactive` 在无 tty 时 warn 提示已退化

## 修复方向(已与编排者确认)
改 `shouldPrompt`,复用已传入的 `interactiveSetByUser` 来识别「显式 opt-out」:
```ts
function shouldPrompt(input: DecisionInput): boolean {
  if (input.yes === true) return false;
  if (input.interactiveSetByUser && input.interactive === false) return false; // 仅显式 --no-interactive
  return input.isInteractiveEnv;   // 未传 flag / 显式 --interactive 都落到 tty 判定
}
```
