== Fix 1：交互 read 重定向到 /dev/tty ==
- 把每一个用户交互用的 `read -r -p "..." var` 改为 `read -r -p "..." var </dev/tty`。
  - 原因：管道下脚本 stdin 被占用并 EOF，`</dev/tty` 让 read 直接读控制终端键盘；`read -p` 的提示本就走 stderr（在管道下仍连终端），无需额外改提示输出方向。这是 curl|sh 类安装器的标准做法。
  - 注意：只改"交互式"的 read（带 `-p` 给用户看的、或读用户输入的）；若脚本里有任何非交互、读管道/文件的 read（应该没有，但若有）不要改。
- 若某些 read 不带 `-r` 但属交互，统一补上 `-r`（防止反斜杠被吃），再 `</dev/tty`。
- 保持其余参数与提示文案完全不变。

== Fix 2：bash 守卫（放 shebang 之后、set 之前）==
在 `#!/usr/bin/env bash` 之后紧接一段守卫，用 **POSIX 兼容写法**（这样在 dash/sh 里也能执行守卫本身、友好退出，而不是崩在别的 bash 特性上）：
```
if [ -z "$BASH_VERSION" ]; then
  printf '%s\n' "pisquad 需要 bash 执行。请改用: curl -fsSL https://raw.githubusercontent.com/Nick-LCY/PiSquad/main/pisquad | bash" >&2
  printf '%s\n' "或先下载再运行: curl -fsSL .../pisquad -o pisquad && chmod +x pisquad && ./pisquad" >&2
  exit 1
fi
```
- 放在 `set -euo pipefail` 之前（守卫不依赖 set；在非 bash 下 `set -o pipefail` 也会报错，所以守卫必须先于它）。
- 用 `[ ]`、`printf`、`exit`，不要用 `[[ ]]`、`echo -e` 等。`$BASH_VERSION` 在 dash 里未定义→进入守卫分支。
